# streaming-alert

员工非生产性活动的流式告警计算库。一个 `AlertTracker` 实例对应一名员工：
输入已分类好的非生产性活动区间，输出告警段。不做采集、分类策略与通知；
调用串行执行，无持久化与崩溃恢复。

## 快速开始

```python
from streaming_alert import AlertTracker

tracker = AlertTracker()                 # 窗口 2h，阈值 45min（默认）
tracker.add([(0, 3_600_000)])            # 一批 (start, end) 区间
closed = tracker.advance(10_800_000)     # 推进水位，返回新闭合的告警段
assert closed == [(2_700_001, 8_100_000)]
watermark, d, open_since = tracker.state()
```

- `add(intervals)`：接收一批 `(start, end)`。要求 `0 <= start < end` 且
  `start` 不早于当前水位；区间可乱序、重叠、重复，重叠部分只累计一次。
- `advance(t)`：把水位推进到 `t`（不得回退），完成所有不晚于 `t` 的告警
  判定，按起点递增返回此次新闭合的告警段；每段只返回一次，未闭合的告警
  不会因推进被切碎。即使不再收到活动，继续推进也会正确关闭告警。
- `state()`：返回 `(水位, D(水位), 未闭合告警起点或 None)`。

运行测试：`python3 -m unittest discover -s tests`

## 时间边界语义

- 时间是非负整数毫秒；区间为左闭右开 `[start, end)`；时刻 0 之前没有活动。
- 对每个整数时刻 `t`，`D(t)` 是窗口 `[t - 7_200_000, t)` 内被至少一个活动
  区间覆盖的总毫秒数；当且仅当 `D(t) > 2_700_000`（严格大于）时处于告警。
- 告警段为左闭右开的最大连续整数段：起点是第一个满足条件的整数时刻，
  终点是之后第一个不满足条件的整数时刻；终点不晚于水位才会返回。
- 因为所有端点都是整数，`D` 在整数时刻取整数值，阈值边界精确到 1 毫秒
  （例如 `D` 从 2_700_000 涨到 2_700_001 的那一刻即为告警起点）。

## 实现与复杂度依据

- 用 treap 维护输入区间的**并集**（互不相交、按起点有序）。新区间保证
  `start >= 当前水位`，因此水位以下的覆盖已经定型，允许惰性、一次性地
  发出事件，且永不需要重扫全部历史。
- 每个并集区间 `[a, b)` 对 `D` 的贡献是一个梯形，等价于 4 个斜率事件：
  `+1@a`、`-1@b`、`-1@a+W`、`+1@b+W`（`W` 为窗口长度）。左事件在起点越过
  水位时发出，右事件在终点不晚于水位（区间不再可能被未来输入合并）时发出；
  每个区间恰好发出一次。事件进最小堆按时间消费。
- 相邻事件之间 `D` 是斜率 ∈ {-1, 0, 1} 的线性函数，阈值穿越用整数运算
  解析求出，**不按毫秒/秒/分钟逐格推进，也不用固定桶近似**；空白时间
  跳跃是 O(1) 的（见 `tests/test_stress.py` 的空跳用例）。
- 总处理量 `O((N + Q) log(N + 1) + A)`：`N` 个输入区间（每个至多引发
  常数次 treap/堆操作）、`Q` 次推进（每次常数次查找）、`A` 条闭合告警。
- 内存只随尚未越过水位的输入边界和最近一个窗口（2 小时）内的覆盖变化
  增长：`end + W <= 水位` 的并集区间立即从 treap 中剪除，已返回的告警
  不留任何状态。压力测试（30 万区间 / 10 万次推进 / 20 年跨度）中流式
  运行的 treap 峰值仅个位数节点，结束后结构完全清空。
