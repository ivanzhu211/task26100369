# streaming-alert

员工非生产性活动的流式告警计算库。一个 `AlertTracker` 实例对应一名员工；
输入是已完成分类的非生产性活动区间，输出是告警段。不做采集、分类策略与
通知；调用串行执行，无持久化与崩溃恢复。

## 快速开始

```python
from streaming_alert import AlertTracker

tracker = AlertTracker()                 # 窗口 2h，阈值 45min（默认）
tracker.add([(0, 3_600_000)])            # 一小时活动，左闭右开
alerts = tracker.advance(10_800_000)     # 推进水位到 3h
assert alerts == [(2_700_001, 8_100_000)]
print(tracker.state())
# AlertState(watermark=10800000, covered=0, open_alert_start=None)
```

运行测试：

```bash
python3 -m pytest tests/ -q          # 功能 + 随机对照 + 压力（约 15s）
python3 -m pytest tests/ -q -s       # -s 打印压力用例的耗时与峰值内存
```

## API

- `AlertTracker(window_ms=7_200_000, threshold_ms=2_700_000)`
  初始水位为 0。窗口与阈值可注入（测试用小尺度参数对照暴力实现）。
- `add(intervals)` 接收一批 `(start, end)` 区间（可乱序、重叠、重复）。
  要求 `0 <= start < end` 且 `start >= 当前水位`，否则抛 `ValueError`。
  重复/重叠区间只累计一次覆盖。
- `advance(t)` 将水位推进到 `t`（`t >= 原水位`，否则抛 `ValueError`），
  完成所有不晚于 `t` 的判定，返回此次新闭合的告警段列表，按起点递增。
  每段只返回一次；未闭合的告警不因推进而切碎。
- `state()` 返回 `AlertState(watermark, covered, open_alert_start)`：
  当前水位、该时刻的 D 值、未闭合告警的起点（无则 `None`）。

## 时间边界语义

- 时间为非负整数毫秒；活动区间为左闭右开 `[start, end)`；时间 0 之前无活动。
- `D(t)` = 窗口 `[t - 7_200_000, t)` 内被至少一个活动区间覆盖的总毫秒数。
- 告警当且仅当 `D(t) > 2_700_000`（严格大于；恰好 45 分钟不告警）。
- 告警段为左闭右开整数段 `[a, b)`：`a` 是第一个满足条件的整数时刻，
  `b` 是之后第一个不满足条件的整数时刻；`b <= 水位` 时才返回。
- 示例：`[0, 3_600_000)` 使 `D(t)` 在 `t=2_700_001` 首次越限，
  在 `t=8_100_000` 回落到阈值，故告警段为 `[2_700_001, 8_100_000)`。

## 实现与复杂度依据

`D(t) = C(t) - C(t - W)`，其中 `C(x)` 是活动区间**并集**在 `[0, x)` 的覆盖
长度。`C` 是斜率 0/1 的分段线性函数，因此 `D` 连续、分段线性且斜率属于
`{-1, 0, 1}`，拐点只出现在并集区间端点及端点 `+W` 处。越限点满足
`D = 阈值`，由整数端点与整数阈值推出，必为整数，故全部计算保持整数
运算，边界精确到 1 ms，无逐格推进、无固定桶近似。

- **数据结构**：并集区间存放在随机 treap 中（按 start 有序，子树增广
  覆盖总长与最大 end）。插入即合并重叠/相邻区间；查询 `C(x)`、点覆盖、
  端点范围扫描均为 `O(log n + k)`。
- **add**：每条区间一次合并插入，`O(log n + k)`，被合并删除的节点均摊
  到其插入时刻，总计 `O(N log N)`。
- **advance**：只做两次不相交的端点范围扫描——直接事件 `(t0, t1]` 与
  镜像事件 `(t0-W, t1-W]`（端点滑出窗口，斜率取反）——加上 `O(log n)`
  的初值查询。每个端点在整个生命周期被扫描常数次，总事件量 `O(N)`；
  每次推进 `O(log n + k)`，合计 `O((N + Q) log (N+1) + A)`。
  空白时段没有端点，大步跳跃只花 `O(log n)`，绝不逐时刻计算。
- **内存**：每次推进后删除 `end <= 水位 - W` 的区间（它们对所有未来
  判定无影响）。存活状态只包含窗口 `W` 内的覆盖变化与尚未越过水位的
  输入边界，与已结束历史、已返回告警数量无关。
- **一致性**：判定只依赖并集端点事件流，与拆批、到达顺序、推进节奏
  无关；同一区间集合推进到同一水位必然得到相同的已闭合告警与状态。
